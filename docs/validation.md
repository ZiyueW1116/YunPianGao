# 验证范围

## 公开测试

调度测试覆盖阈值、成功与失败事件、新输入竞争、过期结果丢弃、提交指纹变化、跨会话隔离、重复触发、失败恢复、direct 策略和卸载取消。

`test/runtime.py` 使用真实 OpenCode 接口和本地合成模型服务，检查未触发、准备后提交、输入到达时的并发接续、摘要请求失败，以及 direct 原生路径。每个场景使用新的会话库，并在停止进程后做 SQLite `quick_check`。

这些测试用受控的回复和 token 数验证调度，不证明模型压缩后仍保留全部事实或约束。它们不连接外部模型，也不需要模型账号。

## 模型质量

已有隔离长会话续跑实验观察到不同的接续结果和代码错误。原始会话和评测轨迹不随项目公开，不能把它们当成公开可复现的性能基准。

当前适配器使用自定义摘要提示，与 OpenCode 原生同步摘要的提示、工具定义和生成预算不同。后续输入大小相近也不代表生成过程等价。网关还可能忽略或重新解释输出上限。

摘要质量、临时约束的作用范围、模型随机性、保留历史以及调度时机应分别控制。研究调度本身时，需要统一摘要生成方式并重复生成摘要；仅重复固定摘要后的续跑不能覆盖全部随机性。

## 已验证环境

- OpenCode 2.1.4，文本摘要路径。
- 公开核心测试使用 Node.js；构建输出为 ESM。
- 其他 Harness、其他 OpenCode 版本和原生不透明压缩格式没有可用的适配验证结论。

YunPianGao 不承诺摘要无损、质量等价或吞吐提升。
