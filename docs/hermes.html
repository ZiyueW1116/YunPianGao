一个明确入口

create_hermes_session() 包装真实的 AIAgent.run_conversation()；python -m yunpiangao_hermes 提供同一实现的终端入口。源码固定于 f0d94882e89ab8d4098b5bb2f166adfb9ee0a0ab，要求从干净的固定版本 checkout 应用 docs/hermes/host.patch，停放契约版本为 3。

首版不接管原版 Hermes CLI、Gateway 或 HTTP API 的完成消费者。API 写入 timeline 不等于发生新模型轮次，CLI/Gateway 也有各自的唤醒规则。这里的实际接续由嵌入入口自己的执行队列负责。

安装、参数、使用示例和固定源码链接见 Hermes 使用说明。补丁可由 scripts/prepare_hermes.py 重复核验和应用。

两层边界与语言边界

核心拥有语义

一次执行，多次等待

任务终态与单次等待分离。超时、新输入、interrupt 结束等待；独立取消才改变任务。核心保留结构化依赖、deadline 和恢复原因。

适配拥有宿主

原生对象与合法提交

Python 保留具体 ProcessSession、SubagentHandle 和原生压缩候选。核心只接收快照、摘要正文和指纹，不操作聊天表，不调用 Python 模型 SDK。

等待的代码流

  1. 创建具体执行。start_process 经过原生 terminal 范围、middleware、审批与执行链。默认配置下，要求批准且无人应答的命令会被阻止。start_subagent 调用正式生命周期服务，发布后与父轮中断分离。
  2. 注册 handle 与单次等待。Python 将执行对象包为 TaskSource，核心 register → begin 保存 owner、executionID、wait ID 与 deadline；尚不允许接续。
  3. 正常工具结果后停放。宿主补丁在整批工具成功收尾后调用 tool_round_boundary，以 runtime_parked 正常结束。finalizer 持久化工具结果与状态文本。
  4. 真实循环返回后激活。run_conversation() 已完成收尾，入口才调用 activate(waitID)。提前完成或零期限结果保留在 ready 状态，后到的新输入也不会撤销已经结算的结果。停放失败时只收尾本次等待，底层任务可继续。
  5. 运行时查询与结算。零秒等待先复核指定 handle。复核期间接纳新输入或收到显式中断时，旧轮放弃注册。活跃等待默认每 500 毫秒查询原生对象，不唤醒模型；完成、失败、取消或超时竞争同一次结算，原生通知遗漏不会漏唤醒。
  6. 接纳与实际接续。同一 wait ID 只排队一次普通输入；压缩或当前轮结束后，由串行队列进入新一轮 run_conversation()。用户输入使未结算等待收尾，不额外发送一次接续。
工具批次中的其他调用继续正常完成。等待不会伪装为工具失败，不调用底层 interrupt 来模拟正常停放，也不通过模型查询或长 sleep 等任务。

数据流：运行时关系与聊天内容分开

数据所在位置如何进入下一轮
ProcessSession / SubagentHandlePython source 映射，绑定一次实际执行转为 TaskSnapshot：状态、结果、完成时间与错误。
TaskHandle / WaitRecord现有 TypeScript runtime依赖元数据每轮重新注入；接续携带完整结果和恢复原因。管道分块读取累积快照。
接纳过的 wait IDPython 进程内集合接纳与排队之间无 await；同 ID 重试不产生第二轮。
聊天消息与压缩记录Hermes 原生会话设施通过 run_conversation 与 compress_now 生成；适配器不直接修改聊天库。
临时摘要与原生候选Python 保留候选；核心持有正文和指纹资格在 ContextEngine.compress 的原生 lease 内复核，合法后交回宿主提交。

任务输出作为普通用户上下文，不能提升为 system 指令。聊天压缩不会删掉运行时依赖；聊天持久化也不会重建已退出进程的执行句柄。

空闲摘要：准备、失效、复核、原生提交

准备阶段 · 不持主队列

只接受实际完整回答

run_conversation() 成功返回后记录用量。核心默认在 1,500 毫秒空闲后检查 100,000 token 阈值；原生压缩器的工作副本生成候选，不写入主会话数据库。

停放工具轮、失败、中断不作为完整回答。原生没有生成摘要时跳过提交。

提交阶段 · 原生事务

同一输入资格，才允许替换

compress_now → _compress_context → ContextEngine.compress。在原生 lease 内重算消息、输入版本、模型、system、工具、压缩参数与依赖的指纹，调用 takePrepared，再交回原生候选。

指纹不符即取消替换；候选检查、原子归档及写入继续由 Hermes 负责。

交错实际行为
准备期间新输入立即推进输入代次，旧摘要不提交；原任务继续。
原生提交期间新输入输入保留在调用队列，事务结束后才接纳，不丢弃输入。
压缩期间任务完成核心结算并按 ID 接纳；模型请求等压缩结束后才进入队列。
压缩调用 on_session_end这也可能来自 commit_memory_session，不能据此关闭适配器。真实 reset、close、模型与 session 身份变化另行失效。
select_context() 只替换单次请求，不能作为持久压缩。on_turn_complete() 是 best-effort，不能作为唯一收尾证据。首版要求原地文本压缩，并关闭独立记忆、后台复盘、checkpoint、micro-compaction 和原生 prepare-ahead。

生命周期与资源归属

操作等待底层执行
timeout / 新输入结束尚未结算的等待。新输入由正常队列处理已发布任务继续；相同 handle 可重等。
interrupt结束等待，中断信号只作用于当时在途的父模型轮独立子执行与进程继续。
cancel_task继续复核实际终态针对具体执行调用原生取消；回执不是终态。
close撤销调度与接续资格，保留最后快照工具交接子执行后统一请求取消。尚未取得 worker 的独立子执行可直接取消和释放资源。原生线程与子结果收尾后释放宿主；原生 close 可清理其拥有的进程。
reset / 模型更新 / session 变化旧适配实例失效新会话须创建新实例；不迁移 handle。

宿主在子对象构造后和 executor 工作项开始时检查关闭。关闭先于准入时，宿主释放子对象，既无子模型请求也无云片糕 handle。所有 close 调用等待同一次清理，单个调用方取消不会中断清理。在途 prompt 取消后，下一轮仍使用宿主已返回的历史。取消已进入原生事务的 compact 时，适配器等待事务返回并安装历史。压缩期间用 interrupt 结束等待时，事务继续，下一条输入仍进入模型。

Hermes 子 Agent 收尾会清理其拥有的后台进程。独立子执行由所属服务持有，宿主全局结果过期后仍可用原 handle 查询。入口不提供原生 CLI 的 branch/reload，不能把旧实例放进新的会话。首版没有跨重启恢复或持久化任务框架。

测试实际经过的路径

回环 HTTP 模型替身 → 原生工具声明与执行 → 真实 terminal/进程或 SubagentLifecycleService → 正常工具轮停放 → 共用 TypeScript runtime → 新一轮真实 AIAgent 循环。压缩场景还经过原生 SQLite 提交，检查活动历史确实替换。

覆盖完成、提前完成、失败、timeout 重等、新输入与请求中输入、独立取消、interrupt、批次、丢失回执、等待期间压缩、空闲摘要、指纹拒绝，以及创建失败和关闭竞争。回归还核对默认审批、停放前已结算结果、子结果过期重等、取消后历史、关闭等待超时、子执行准入和超过 16 MiB 的快照。补充用例覆盖满载关闭、停放失败收尾、取消压缩后的模型历史、零秒复核及复核期间的新输入。用例还覆盖显式中断与零秒复核交错、迟到的父轮中断、压缩期间结束等待，以及其他会话占满 executor 时的关闭。核心已有竞争与查询补偿回归继续通过。
