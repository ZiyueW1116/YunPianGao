空闲时准备摘要
以执行 handle 等待与接续

Cordis 插件接入 DeepSeek 官方执行循环；核心决定摘要资格、单次等待与竞争结算，宿主保留执行、输入、压缩和生命周期的所有权。

固定版本 0.2.2-alpha.3 · 源码 05b1cae8db6e674c5685101494d4eec24652424a · Node.js ≥24.9.0 · 首版只保留进程存续期间的 handle

两层边界

云片糕核心

scheduler.ts 拥有回答后的空闲调度、摘要失效与 takePrepared 提交资格。

wait.ts 拥有具体执行 handle、单次 WaitRecord、deadline、第一次结算、事件丢失补偿和一次有效投递。

核心不导入 DeepSeek SDK，不按 Harness 名称分支，不访问聊天库。

DeepSeek 适配与宿主

adapters/deepseek.ts 注册工具，把 subprocess、activation、Agent 与原生 Session 连接到核心端口。

宿主拥有工具策略、执行范围、普通输入、维护队列、原生摘要载荷与历史替换。摘要补丁只增加准备入口与同步提交 guard。

工具执行与任务数据

01

发布执行

宿主提交含 handle 的成功结果后，核心才开放查询和等待。若结果被屏蔽，适配器收尾未发布执行。

02

停放等待

正常等待在原生 idle 时激活。步骤准备期间已有新输入时，旧请求返回 user_input，宿主继续处理输入。

03

按期限结算

核心对照完成时间或观测时间与 deadline。达到期限即超时，已确定的原因保持有效。

04

实际接续

runtime 送普通输入。原生 inbox 插入日志保留已消费消息的接纳证据，重试共用同一等待 ID。

新输入会收尾尚未结算的等待。输入和超时都保留底层执行，同一 handle 可重等。cancel_task 独立取消任务。

摘要代码流与原生提交

黄色节点需要固定版本宿主补丁

官方 summarize hook 只决定生成内容；SDK JSON-RPC 客户端也没有提前摘要提交扩展。补丁提供无锁的原生准备，以及紧邻同步替换的提交 guard。未知版本和文件校验失败时拒绝修改；不通过写聊天文件补齐能力。

核心保存文本占位与指纹，原生 ContentBlock 数组、usage、rawOutput 与 llmStreamCall 由适配层完整保留。失效结果不提交，也不退回额外模型摘要。

数据的所有权与寿命

数据所有者有效范围与压缩行为
TaskHandle / TaskSnapshot核心 + 执行源绑定一次执行；进程内保留。压缩后以普通上下文重新注入依赖。
WaitRecord / deadline / reason核心每次等待独立；超时可重等。一个结算原因与一次有效接续。
原生 SummaryResult适配层暂存完整载荷；提交前复核 epoch、模型、header、replay、surface 与依赖。
接续消息接纳事实原生 Sessioninbox 插入日志在消费后仍存在；压缩不删除接纳证据。
进程 / activationDeepSeek 宿主服务取消是独立操作；close 收尾未发布创建与子 Agent，独立进程由宿主服务继续拥有。

验证能证明什么

已运行的路径

正式 dsh --profile sdk-minimal、Loader、原生工具 pipeline、Agent loop、subprocess、activation、compaction 与隔离 JSONL persistence。

回归覆盖步骤准备期间的新输入、启动结果拦截、期限竞争和压缩后的实际接续。压缩场景从模型请求解析 handle、deadline、reason 与任务结果。

SDK 与模型边界

SDK 的 run() 在首次 idle 返回。调用方可保持会话订阅，按等待 ID 观察接续。profile 回归使用 workspace-write，官方模板默认 danger-full-access。

模型替身预设工具选择和文本。真实模型自主行为、摘要保真度、外部 provider、Windows、Web UI 和文件 HMR 仍待验证。

普通任务父请求 3 次；超时重等 4 次；用户输入后重等或独立取消后等待 5 次。子 Agent 另有 1 次请求。额外唤醒与长 sleep 的断言来自合成流程；延迟观测不构成性能承诺。
