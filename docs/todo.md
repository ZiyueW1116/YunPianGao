# 后续工作

## 任务等待的支持范围

`start_process` 和 `start_subagent` 返回具体执行的 handle，`wait_for` 在成功、失败、取消、超时或需要介入时接续 session。等待期限与依赖由进程内 runtime 保存；用户输入只结束等待，取消任务使用独立的 `cancel_task`。

已覆盖注册前完成、重复通知、完成与超时竞争、查询断线恢复、接续响应丢失重试、用户输入、独立取消，以及等待期间压缩后的依赖恢复。OpenCode 2.1.4 通过原生中断和 synthetic 输入实现接续。接口和宿主能力边界见 [适配契约](adapters.md#任务等待)，测试覆盖见 [验证文档](validation.md)。

## 待实现与待验证

- [ ] 为进程重启后的 handle、等待期限与恢复原因提供持久化，并验证事件重放、接续幂等和任务归属。当前状态只在插件进程内保留。
- [ ] 适配原生后台 `shell`、`subagent` 或其他长工具调用的执行标识，协调宿主已有完成通知。当前仅支持插件启动的任务，不能直接等待原生任务标识。
- [ ] 接入宿主提供的真正执行停放接口，保留工具成功返回状态并解除同一步单独调用的约束；当前 2.1.4 公开接口没有该能力。
- [ ] 接入宿主公开的表单查询能力，以恢复断线期间遗漏的表单创建与关闭事件。当前 2.1.4 插件接口没有该能力，具体边界见[适配契约](adapters.md#opencode-214)。
- [ ] 对同一批任务比较固定 `sleep`、模型反复查询和 `wait_for`，记录完成到接续的延迟、不必要的模型唤醒次数、无理由长 `sleep` 使用率及 token 用量。现有合成替身预设工具选择，只验证等待语义，不能证明真实模型会主动选择 `wait_for`，也不能证明改善幅度。
- [ ] 验证 Windows 取消及进程树处理。真实入口检查已使用 macOS arm64，其他平台由对应环境补充验证。
- [ ] 支持复用既有 working subagent、任务输入与嵌套启动；需要先定义执行代次及父子权限继承，避免把旧轮结果交给新等待。
