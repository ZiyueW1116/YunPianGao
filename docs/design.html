云片糕 · YunPianGao
Pi Harness 与两层架构

两条独立的业务流程，共用一个 Pi session：在回答后的空闲窗口提前生成摘要；在后台任务尚未结束时停放推理，待结果或期限到达后接续。本文把模块归属、调用顺序和数据去向分别展开。

01代码实际负责什么

云片糕是嵌入 Pi 的进程内能力。它管理摘要调度与任务等待的业务语义，通过适配层调用宿主的执行、模型和会话接口。实际模型推理、工具循环和聊天持久化由 Pi 管理。

摘要调度域

先准备，再复核提交

完整回答后检查 token 阈值，在主执行循环外准备摘要。新输入使旧结果失效；原生 compact 提交前，再比较上下文指纹。

拥有：空闲代次、延迟计时器、临时摘要与提交资格。

任务等待域

一次执行，可以等待多次

启动进程或子 Agent 后返回具体执行的 handle。一次等待有独立期限和结束原因；超时、输入或停止等待不会隐式取消任务。

拥有：任务快照、等待记录、结算竞争、激活与接续重试。

明确边界：主要入口是正式 Pi Coding Agent SDK，尚无可直接用 pi -e 加载的独立扩展入口。没有 Pi Durable、跨重启任务恢复、通用 Harness 平台或独立聊天数据库。

对象谁拥有云片糕的实现范围
Agent 执行循环、模型请求、会话树Pi SDK调用公开接口；在原生轮边界决定停放，使用原生消息发起接续。
摘要何时准备、何时失效核心 scheduler业务规则、空闲代次、阈值、摘要消费资格。
任务与单次等待核心 wait runtimehandle 归属、期限、结束原因、一次有效投递及结构化快照。
操作系统进程、独立 Pi 子 session适配层创建实际执行、采集结果、处理取消信号，转成 TaskSource。
模型是否主动选择 wait_for模型行为，尚未验证工具说明引导模型；当前合成测试不证明自主工具选择。

02两层架构：语义在核心，接口在适配

源码依赖由适配层指向核心层。核心用端口描述实际调用边界；Pi SDK、宿主消息和工作目录只出现在适配层。图中的宿主设施属于外部系统，不构成云片糕的第三层。

箭头表示源码依赖 / 设施调用方向。核心通过端口回调适配层实现属于运行时调用，不是反向 import。

CompactionPort

读取完整回答、准备摘要、发起原生提交、等待提交完成。Pi 的 compact 本身等待完成，因此其 wait() 为空实现。

TaskSource

read / subscribe / cancel 把具体执行转为统一快照。事件用于低延迟，查询用于补偿遗漏。

WaitPort

resume(record, signal) 将已结算等待落实为真实 session 接续，按同一等待 ID 识别已接纳结果。

核心保留已有合理实现；进程执行被提取为共用适配模块。没有为了两层命名而增加通用基类、动态注册器或多层工厂。

异步事件可在任意两步之间到达。核心将“注册等待”和“允许发送接续”分开，覆盖任务在停放前完成的情况。

进程任务如何完成

spawn(command, args) 不经过 shell。stdout / stderr 合并保留尾部；close 事件形成 exitCode、signal、output、truncated 结果。正常退出为 succeeded，其他退出为 failed；请求取消后由 SIGTERM 退出才标记 cancelled。

子 Agent 如何完成

创建独立 Pi session，共享当前 ModelRuntime、模型、thinking level 和目录，禁用扩展。由该次 prompt() 的完成与最终 assistant 消息确定成功、失败或取消，随后 dispose 子 session；不从压缩控制项或 idle 时间推断完成。

两道资格：state = ready 表示等待已结算；active = true 表示宿主已到达可接续边界。两者都满足才可投递。Pi 允许同批其他工具先正常完成，但同一轮只注册一次等待。

05数据流：执行、等待记录与聊天内容分开保存

06压缩的代码流：在宿主边界消费摘要

空闲并不直接等于允许压缩。Pi 先确认 session 空闲，且最后相关原生条目为 stopReason = stop 的 assistant 回答；核心再检查用量阈值。等待工具之后的 toolResult 不满足这项完整回答筛选。阈值使用最近完整回答的 input + output + cacheRead + cacheWrite 之和，不是会话累计计费。

01 · 调度agent_settled → engine

非 aborted 事件报告 succeeded；延迟默认 1,500 ms，再筛选完整回答与 100,000 token 阈值。

02 · 准备prepare() → 摘要模型

读取原生当前投影，调用 Pi generateSummaryWithUsage，经当前 ModelRuntime 发送，不创建用户输入。

03 · 再确认仍在同一空闲代次？

核心检查 idle / epoch 与非空摘要；Pi 再检查 isIdle 和 pendingMessageCount。

04 · 提交session.compact() → hook

在 session_before_compact 重算指纹并 takePrepared；原生 Pi 持久化摘要并刷新上下文。

原生提交回调

takePrepared 的三种结果

  • 返回文本：提交已有摘要，使用原生 preparation 的 firstKeptEntryId 与 tokensBefore。
  • 返回 undefined：没有可消费的预备结果，保留宿主原生压缩流程。
  • 抛出 StaleSummaryError：适配器返回 { cancel: true }，取消这次压缩；不以原生重新生成掩盖过期摘要。

不能只把异常抛给 Pi：宿主扩展 runner 会捕获 hook 异常，需要明确返回取消。

核心 scheduler 的 epoch

每次输入或执行阶段变化推进。延迟任务保存其代次，准备返回后必须仍是同一空闲轮。它表达摘要的调度资格。

src/scheduler.ts · State.epoch / current()

Pi 适配器的 epoch / modelEpoch

输入及模型选择推进 epoch；context 回调记录 modelEpoch。旧请求中的 wait_for 若遇版本不一致，直接返回 user_input，不注册过期等待；epoch 也进入摘要指纹。

src/adapters/pi.ts · input / context / model_select

提交范围：摘要覆盖当前完整投影，原生选择的尾部继续保留，可能与摘要重复。临时摘要的 usage 未写入主 session 统计。Pi 入口只支持 prepare-then-commit；模型生成预算与格式使用 Pi 原生实现。这里不提供覆盖所有外部扩展副作用的通用事务或 CAS。

07等待与压缩怎样配合

等待依赖不以摘要文本为唯一来源。任务与等待留在 runtime 的 Map 中；压缩只改变 Pi 的聊天投影。下一次 context 回调从内存重新取得依赖，所以摘要遗漏 handle 文本不会消除现存的运行关系。

同一屏障在原生压缩结束时释放；任务结算资格与发送时机是两件事。关闭时的取消信号可打断本地屏障等待。

摘要准备期间的新输入

正常进入 Pi，推进输入版本并使核心空闲代次失效。模型摘要请求可能继续计算，但返回的旧结果不被提交。

原生 compact 期间的新输入

Pi 1.5.0 拒绝新 prompt。嵌入方应保留被拒绝的文本，待压缩结束后再提交。适配器没有添加输入缓存或自动重试队列。

    09集成与生命周期：关闭、失效与资源归属
    

    操作本次等待独立进程子 Agent接续行为
    

    timeout / 新输入结算当前等待继续执行继续执行timeout 由 runtime 接续；新输入由 Pi 接续。
    

    ypg.interrupt()记录 interrupted继续执行独立子 session 继续同时 abort 父 session；停止该次等待的后续投递资格，已就绪结果遵循先结算规则。
    

    cancel_task(handle)仍按 source 终态复核向该进程组发送 SIGTERM对目标 child 调用 abort请求回执不是终态证明；等待在观察到结果后接续。
    

    ypg.close()关闭 runtime，停止定时器与本地投递继续，输出被消费到退出abort 父 session 与 children，等待在途创建及子结果收尾，再 disposeruntime.close 生效后不再发起投递；已接纳输入不能被撤回。

    关闭的代码流
    

    

    01 · 撤销资格closed = true
    先公布共享关闭 Promise，同步标记关闭并调用 engine.close / runtime.close。新工具与 interrupt 拒绝操作，后续回调不再调度或投递。
    

    02 · 停止推理abort 父与子 session
    与核心清理并行启动。尚未结算的等待记录 closed；已确定的原因保留。独立进程继续执行。
    

    03 · 等待收尾starting + children
    等待在途创建返回；迟到对象复核失效后释放，不启动 prompt。等待已运行子 prompt 的结果处理与 dispose 完成。
    

    04 · 完成释放同一个 closing Promise
    清理子资源、轮边界状态并 dispose 父 session。并发调用与 abort 监听器的同步重入，都等待这次完整清理，SDK 资源只释放一次。
    

    

    入口拥有 DefaultResourceLoader，不接收自定义 resourceLoader；其余原生创建选项可传入。资源加载、SDK 创建或回调安装失败时，父入口关闭已经拥有的资源并传播错误。子创建在每个异步边界检查 closed 与工具 AbortSignal；创建或绑定失败时清理已返回的 child，再向工具调用方传播错误，不发布 handle。
    

    适配层状态保存什么关闭时如何消费
    

    starting从加载资源到发布 handle 的创建 Promise。close 等待这些调用返回；它们在边界处拒绝迟到启动，并释放已创建对象。
    

    children已拥有的子 session → prompt 收尾 Promise；创建中尚无 prompt 时为 undefined。abort 已创建对象；等待结果收尾，避免重复 dispose 或关闭后仍处理子结果。
    

    sessionID适配实例创建时的固定归属。内存 fork 即使复用并改写 SessionManager，旧快照仍查询原 session 的状态。
    

    closed / closing入口操作资格与同一次完整清理结果。关闭立即生效；先公布 Promise，再触发 abort；重复或同步重入调用等待同一结果，不提前返回或重复清理。
    

    

    shutdown、fork 与 reload 的失效边界
    

    原生 session_shutdown 关闭当前适配实例。文件与内存 fork 的新实例拥有空 runtime，不接管旧 handle。reload 会重新调用原 inline extension 工厂；closed 工厂不注册工具或事件，也不重新连接已释放的原生 session。新生命周期须重新调用 createPiSession。保留的旧工具及 interrupt 抛出关闭错误；snapshot 仍可读取关闭时的状态，其中 working 不代表外部任务已结束。已释放的原生 session 不能继续使用。
    

    Pi 的加载、创建与绑定接口没有这里可用的统一取消参数；close 等待在途调用返回后清理，不保证固定完成时限。已经被宿主接纳的输入不能撤回。直接调用空闲状态的原生 session.abort() 可能没有执行事件，停止停放等待应使用 ypg.interrupt()。
    

    进程生命周期
    不接受交互式 stdin；环境与目录来自宿主。POSIX 取消进程组；Windows 分支只取消直接进程，未做真实平台验收。忽略 SIGTERM 的进程可能继续运行，不自动强杀。
    数据生命周期
    TaskSource、结果、期限与恢复原因在进程内。原生聊天持久化可能保存工具与接续记录，但适配器不会据此重建执行句柄。没有跨重启恢复承诺。

    实现基线的验收记录，日期 2026-11-03；macOS arm64、Node.js 26.3.1、Pi 1.5.0。20 个执行循环场景使用真实 SDK 与本机模型替身，回复和工具选择预设。另有 21 个生命周期场景通过真实入口与原生对象，在加载、创建回执、绑定和订阅边界注入故障及门闩；其中部分场景不经过模型轮次。观察到额外父模型唤醒 0、长 sleep 调用 0；毫秒观测不是生产性能保证。
    

    性质证据范围不能据此推断
    

    Pi 实际停放与接续进程 / 子 Agent 完成、失败、输入、取消、超时重等；提前完成、回执丢失、同批工具及模型流中输入。真实模型会自主选择 wait_for；其他 SDK 版本行为相同。
    

    压缩与等待配合进程和子 Agent 等待期间 compact；任务在压缩请求阻塞期间完成；后续模型收到 runtime 依赖。所有外部扩展修改都受通用原子事务保护。
    

    预备摘要的有效性空闲准备与复用、新输入失效、提交前系统提示变化时取消；没有额外原生摘要 fallback。真实模型的摘要质量、信息保真度或成本收益。
    

    Pi 生命周期竞争父 / 子创建失败；加载与绑定中 close；迟到创建回执；工具取消；并发 close；运行中子推理只释放一次；独立进程继续；compact 屏障中的投递关闭；原生 shutdown、文件 / 内存 fork 和 reload 失效；abort 同步重入时同一 Promise 与一次 SDK 资源清理。任意第三方扩展都可被强制终止；资源加载或绑定永不返回时仍保证关闭期限。
    

    核心竞争与补偿重复通知、完成 / 超时竞争、断线查询恢复、介入解除、handle 归属、卸载与同 ID 重试。Pi 禁用扩展的子 session 已接通 input_required 来源。
    

    OpenCode 兼容此前通过 6 个压缩 + 32 个等待真实入口场景；本次保留适配单测，未重跑这些真实入口。OpenCode 结果可以代替 Pi 验收。
    

    

    创建故障注入位于 SessionManager.buildSessionContext，早于 AgentSession 分配；已返回对象的失败清理由绑定和订阅故障覆盖。SDK 内部“分配后、返回前”的任意异常资源释放未验证。同步重入测试使用正式 agent.subscribe 的 AbortSignal 与公开 registerSessionResourceCleanup，直接统计 SDK 资源清理次数。
    

    当前必须按边界集成
    

    SDK 与 CLI
    SDK 公开 finishTurn 的 end 决策；普通扩展 turn_end 只可要求继续，tool hook 的 terminate 用于阻止工具。适配器采用 SDK 正常轮边界，尚无独立 CLI 扩展入口。
    子 Agent 交互
    Pi 没有 OpenCode 的 Agent 清单与权限审批协议。本实现的子 session 禁用扩展，不模拟 permission / question / form，未转发扩展 UI 介入。input_required 保留在核心契约。
